# 2026-08-27

## What I set out to do

work through Python strings: indexing, slicing, immutability, escape sequences, and f-strings. Build three scripts: a log line dissector, an AWS resource name generator, and an access key masker.

## What I did

Wrote `log_dissector.py`, which takes a raw log line and slices out the timestamp, date, time, year, severity level, event message and affected service. Counted the total length of the log line. Printed an incident summary to show this in a presentable format. Used negative slicing for the message because it sits at the end of the log line.

Wrote `key_masker.py`, which stores an access key id and then masks it in the credentials page using slicing techniques to show only the first 4 and the last 4 characters and the rest in the middle is replaced by asterisk

Wrote `aws_resource_name_generator.py`, which stores an AWS resource name and then derives the short code from the full AWS region name using slicing techniques.

## What went wrong

Built the key master, then printed the unmasked key on the credentials page instead of the masked key because i put the wrong variable in the f string.

The masked width was also not printed correctly because I went off by one `[4:-5]` in the slicing script and it ran clean but gave the wrong output in terms of the number of characters. I also failed to spot the identical bug in a debugging exercise.

## What I would do differently

For the access key leak, I would make sure to confirm if i have put in the right variable and make sure that only the safe form is in scope.

Check the length of the output against the actual length of the input, this would have been obvious if i had printed both lengths and compared them
